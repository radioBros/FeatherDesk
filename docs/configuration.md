# Configuration

FeatherDesk is configured with environment variables (`FD_*`). Branding, SMTP, inbound email and support settings can also be edited in the admin UI. Only the SMTP settings (`FD_SMTP_*`) and the env-defined inbound mailbox (`FD_IMAP_*`) can be locked by the environment: when one of those variables is set, it **overrides** the stored value and the UI shows that field as locked ("set by environment"). Branding and support settings have no environment lock and are edited in the UI only. The one exception is `FD_SELF_REGISTRATION`, which, when set, overrides the self-registration support setting at runtime; the UI does not show it as locked.

The **customer portal switch** (`support.portal_enabled`, default `true`; Administration → System → Support settings → *Customer portal enabled*) has no environment variable: it is not an SMTP/IMAP-style field that the environment can lock, and an operator can change it live without a restart. With it off only admins and staff sign in; see [Switching the customer portal off](DOCUMENTATION.md#switching-the-customer-portal-off).

Configuration errors are reported **all at once** at startup, so you can fix everything in one pass.

### `FD_ALLOWED_ORIGINS`

Extra browser origins of **the same instance**, accepted besides the origin of `FD_PUBLIC_URL`. Use it when people reach FeatherDesk under more than one address, typically a container published on another host port and opened both by LAN address and on the Docker host:

```sh
docker run -d -p 3200:8080 -v fd-data:/data -e FD_SECRET_KEY="$FD_SECRET_KEY" \
  -e FD_PUBLIC_URL=http://192.168.1.50:3200 \
  -e FD_ALLOWED_ORIGINS=http://localhost:3200,http://127.0.0.1:3200 \
  ghcr.io/radiobros/featherdesk:latest
```

- **Format:** comma-separated origins `scheme://host[:port]`. Spaces and empty items are ignored. Each item needs an `http` or `https` scheme and a host; a path other than `/` is not allowed.
- **Default:** empty, so only the origin of `FD_PUBLIC_URL` is accepted.
- **Validation:** an invalid item stops the server at start (exit code 2), reported with the other configuration errors as `FD_ALLOWED_ORIGINS: "…" is not an origin like https://host[:port]`. `featherdesk config check` reports it too.
- **Where it applies:** the CSRF `Origin`/`Referer` check of cookie-authenticated writes and of sign-in, the WebSocket `Origin` check (`/api/v1/ws`) and the `Origin` check of the MCP endpoint (`/mcp`). Items are reduced to `scheme://host[:port]` and compared ignoring case.
- **Not CORS:** requests the browser marks as cross-site are still refused; no other site gets access to a signed-in session.
- **What it does not change:** links in emails, SSO redirect URIs and the setup link always use `FD_PUBLIC_URL`, which must include the published port. Cookies are `Secure` when `FD_PUBLIC_URL` is `https://`; browsers keep those only over HTTPS and on `http://localhost`.

No image is published on `ghcr.io` yet: the tag above is the one `docker build -t ghcr.io/radiobros/featherdesk:latest .` creates from a checkout. With Compose, the published port and address are set in `deploy/.env` too; see [Another host port or address](DOCUMENTATION.md#another-host-port-or-address).

## Module variables

These variables are read by the modules through `config.Env` (and, for the SMTP and IMAP fields, `settings.Overlay`). Like the core ones, every problem is reported at startup. A set `FD_SMTP_*` or `FD_IMAP_*` value overrides and locks the matching field in the admin UI. More context for each group is in [DOCUMENTATION.md §3.3](DOCUMENTATION.md#33-variable-reference).

## Settings without environment variables

Projects, automation and assignment, two-step verification, privacy (GDPR), the notification centre and the MCP endpoint add **no** environment variables. The MCP switch is the settings key `integrations` (`{"mcp_enabled": false}` by default; *Administration → System → Support settings → Integrations*, `PATCH /api/v1/admin/integrations`, see [features/mcp.md](features/mcp.md)). Projects (keys, members, team mapping, per-project SLA overrides, portal branding) are database rows edited under *Administration → Projects* or through `/api/v1/admin/projects` ([features/projects.md](features/projects.md)); the Default project is created by the migration. Their settings live in the database and are edited in the admin UI or by each user: the two-step verification policy (settings key `security`), the retention policy and deletion-request options (`retention`, `privacy`), each team's automatic assignment, automation rules and macros, the agents' *Away* switch and every user's notification preferences.

The canonical list, with the admin UI location and API of each setting, is [Settings stored in the database](DOCUMENTATION.md#settings-stored-in-the-database).
