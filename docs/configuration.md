# Configuration

SimpleTickets is configured with environment variables (`ST_*`). Branding, SMTP, inbound email and support settings can also be edited in the admin UI. Only the SMTP settings (`ST_SMTP_*`) and the env-defined inbound mailbox (`ST_IMAP_*`) can be locked by the environment: when one of those variables is set, it **overrides** the stored value and the UI shows that field as locked ("set by environment"). Branding and support settings have no environment lock and are edited in the UI only. The one exception is `ST_SELF_REGISTRATION`, which, when set, overrides the self-registration support setting at runtime; the UI does not show it as locked.

The **customer portal switch** (`support.portal_enabled`, default `true`; Administration → System → Support settings → *Customer portal enabled*) has no environment variable: it is not an SMTP/IMAP-style field that the environment can lock, and an operator can change it live without a restart. With it off only admins and staff sign in; see [Switching the customer portal off](DOCUMENTATION.md#switching-the-customer-portal-off).

Configuration errors are reported **all at once** at startup, so you can fix everything in one pass.

## Runtime knobs

| Variable | Default | Description |
|---|---|---|
| `GOMEMLIMIT` | derived: 75% of the container memory limit | Go soft memory limit. When unset, it is derived from cgroup `memory.max` at boot. An explicit value wins |
| `GOGC` | Go default (100) | Garbage-collector target |

## Settings without environment variables

Automation and assignment, two-step verification, privacy (GDPR) and the notification centre add **no** environment variables. Their settings live in the database and are edited in the admin UI or by each user: the two-step verification policy (settings key `security`), the retention policy and deletion-request options (`retention`, `privacy`), each team's automatic assignment, automation rules and macros, the agents' *Away* switch and every user's notification preferences.

The canonical list, with the admin UI location and API of each setting, is [Settings stored in the database](DOCUMENTATION.md#settings-stored-in-the-database).
